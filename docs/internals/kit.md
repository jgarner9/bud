# The kit

What `bud kit` syncs into Claude Code, the marketplaces and plugins, the ledger and how the kit is edited.

**Kit** (D56, D77): how Claude works lives in the public `jgarner9/bud-plugins` (plugins `bud` and `bud-ide`), not in bud, so the kit holds no skill or agent. `kit/kit.json` is the manifest of the whole Claude setup (D111; its format, and what `Load` checks, is in [kit-manifest.md](kit-manifest.md)), with `kit/rules/` and `kit/cloud/` beside it, but sync applies only two of its sections so far: the `bud-plugins` marketplace (HTTPS git URL) and the plugins `bud@bud-plugins` and `bud-ide@bud-plugins` (superpowers was dropped, D100). `internal/kit` (`Load`, `Sync` with a dry run, `Ledger`) syncs the embedded `kit/` (`bud.Kit()`); `bud kit sync [--dry-run]|status|ls|unsync` (`internal/cli/kit.go`, swap `kitFS`, `kitClaude`, `installedPlugins` and `kitMarketplaces` in tests; `fakeKit` in `kit_test.go` does all four), and `resyncKit` after an update when a ledger exists. Never run a real sync from tests: they use a temp HOME and a recorded `claude`. Marketplaces (JGA-168): `syncMarketplaces` adds a missing one before the plugins (`Env.Marketplaces` reads `claude plugin marketplace list --json`, `ParseMarketplaces`), refreshes one in the ledger every sync (a failed refresh is a skip), skips one you added yourself, and `removeMarketplaces` takes out a dropped one after the plugins. Plugins (D62, `syncPlugins`) install through `claude plugin --scope user` (`Env.InstalledPlugins` reads `claude plugin list --json`); only a copy that loads in every project counts as installed (`Plugin.machineWide`: user scope, synced, or managed, which is skipped as the policy's), while a project or local one is named in the reason (`localNote`) and never uninstalled, and a ledger entry whose user-scope copy is gone is just dropped (JGA-183); one installed from any other source is yours, and so is one claude.ai syncs (`name@synced`, JGA-177; bud then uninstalls its own copy so the synced one loads; another copy hides it, which sync names with the uninstall command for its scope and the full doctor's `synced plugins` check warns about, `kit.Shadowing` finds every copy, `kit.Shadowed` leaves out bud's (`kit.Owned`: the ledger's, at user scope), doctor names bud's with `bud kit sync` and trusts the ledger only for its own `Dir`, `kit.UninstallHint` (scope, project dir, managed); `kit.ParsePlugins` reads `claude plugin list --json` for both, swap `installedPlugins` and doctor's `pluginList`, JGA-182), and bud's are `plugin update`d at every sync, even from a marketplace you own (JGA-174); one of the same name you installed from another marketplace is yours too, with no second copy beside it (`elsewhere`, D91). bud sets no output style (D78): `removeOutputStyle` (`internal/kit/outputstyle.go`) takes out the `outputStyle` an older bud set in `settings.json` (`Ledger.OutputStyle`), only while it's still that, keeping the rest of the file. MCP servers, skills, agents, commands, output style files and the `CLAUDE.md` block aren't synced any more: the manifest lists servers, settings and rules again, but nothing applies them yet (JGA-249, JGA-250), so MCP servers and their secrets still come from the Claude Code config (clod defines them, reading secrets from the environment, then the keychain under service `bud`) and bud keeps no secrets, and `removeLegacy` takes out what an older sync added (`Ledger.MCP` via `claude mcp remove` while still in `ClaudeJSON`, `Ledger.Files` while still what bud wrote, `Ledger.Instructions` via `withoutBlock`). `kit.json`'s `account.instructions` (`bud-plugins/core.md`, JGA-179) is what `kit.ReadCore` reads from the marketplace's `installLocation` in `plugins/known_marketplaces.json` (file reads only) and compares with the hash `bud kit core --pasted` recorded (`paths.CorePasted`); `remindCore` prints `kit.CoreReminder` after a sync or `resyncKit`, and doctor's `core.md` check (`checkCore`, swap `kitFS`) warns, which the dashboard shows. Doctor's `claude setup` check (`checkClaudeSetup`, full runs only, JGA-175) warns when `claude mcp list` (swap `mcpList`, read by `parseMCPList`, which skips its diagnostics block) lacks one of `Kit.ExpectedServers()` (the servers `kit.json` has on by default) (a claude.ai connector counts, names compared by `mcpKey`), lists one that doesn't connect (failed or needing a login, noting one defined in several scopes; JGA-180) or no rule under the Claude dir's `rules/` (or its `CLAUDE.md`) carries `core.md`'s first line. `bud install` runs `installKit` (D72: syncs only once Claude Code is logged in, since plugins claude.ai syncs show up only then; tests swap `syncKit`). `offerHeadroom` (full profile, JGA-130) offers to set `ai.claude.command` to Headroom's wrapper when it's installed; doctor's `claude command` check warns when that wrapper is missing (tests swap `lookPath`). Editing the kit (D58): `kit.Repo` (`AddPlugin`, `AddMarketplace`, `Remove`) works on a checkout's `kit/` (`kitRepo`: `--repo` or the dev link), `kit.disabled` in `config.json` filters `Sync` by name (`Env.Disabled`; `kit.Turns` also matches a plugin of that name from another marketplace, and `bud kit enable` clears such an entry), a plugin the kit moved keeps bud's old copy and its marketplace until the new one installs (`fromMarketplace`), and `defaultKitFS` reads a dev-linked checkout's kit. A skill, agent or command is changed in bud-plugins, never here.
