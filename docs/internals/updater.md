# The updater

Self-update, rollback, the background check and what runs after an update.

**Updater.** `internal/updater` asks GitHub for the channel's newest release (`Latest`, `Check`): `stable` is `releases/latest`, `nightly` is the rolling release tagged `nightly`, whose *name* is its version (`X.Y.Z-nightly.YYYYMMDDHHMM`). Versions compare with `version.Parse`/`version.Compare` (semver precedence). `bud update --check [--channel]` reports it. Plain `bud update` (`selfUpdate` in `internal/cli/update.go`) installs a newer release first, only for the binary `install.sh` recorded (else it names the right tool, D20): `updater.Fetch` downloads and checks it (the SSHSIG on `checksums.txt`, made by any of the pinned `ReleaseKeys`, D41/D44, then the SHA-256), `CheckBinary` runs it, `Swap` keeps the old one as `bud.prev` and renames the new one in, and the new binary is exec'd with `BUD_UPDATED_FROM` set to do the sync. It then runs the quick doctor checks (`finishUpdate`): if the sync fails, or a check fails that wasn't already failing before the swap (`BUD_FAILING_BEFORE`), it restores `bud.prev` and execs it with `BUD_ROLLED_BACK_FROM`, which syncs the old config and exits 1 with the reason. At launch, `open` first finishes a pending background update (`finishPendingUpdate`), then `startUpdateCheck` starts a detached `bud update --background` once a day (`updater.State` in `~/.local/state/bud/update.json`, log in `~/.cache/bud/update.log`; skipped with `--no-update` and for dev builds). After the sync, a plain `bud update` runs `checkHealth`, the full doctor listing only what isn't OK and exiting 1 on a Fail, skipped with `--no-doctor` (tests swap `doctorChecks`); `finishPendingUpdate` calls `finishUpdate` (sync and quick checks, with rollback) and skips it. Nothing in the update asks questions or touches Claude Code's config (the kit sync and its prompts went in 2.0, D144). Before the doctor, a plain `bud update` (not `--no-doctor`, not `finishPendingUpdate`) runs `refreshBundles` (D98, JGA-187, `internal/cli/bundle.go`): only from the release bud install.sh installed (`installedSelf`, `version.Released`), so a dev build never bakes itself into the app; each app `findBundles` reports is rebuilt in place by `bundleCmd` when `MacInfo.Stale` (or `bundle.LinuxVersion`) says it's out of date, except one that's open (`appRunning`) or a kitty copy when kitty.app can't be found; swap `readMac`, `linuxVersion`, `appRunning`, `installedSelf`. On stable with `update.auto` it swaps the release in and records it as `installed`, so the next launch syncs it; otherwise (nightly, D42) it records `available`, which the dashboard shows as a banner (`update_banner`). Tests fake GitHub with `httptest`, which needs to bind a local port (blocked in the sandbox).
