## 2026-11-20: lifecycle and runtime baseline

- Started at Bud commit `5918229aa7f1455260de4c69e64e209b3c8f8341` and applied the supplied PR #46 lifecycle patch, including the shared Go dispatch helper and tests. The helper is not connected to either runtime.
- Changed the helper to approve and consume in one durable store transaction, eliminating a durable intermediate approval if the process stops between those steps. Expiry is checked after acquiring the lock. The legacy store transitions also reject a stale caller timestamp when the current time is later. The adapter remains responsible for authenticating the reviewer and isolating its store and decision channel.
- Fetched OpenCode 2.3.2 at `c0ad18b402eb2827fc1ee71c171b1177b3fc02d1`. Bun 1.4.4 installed its locked dependencies and built a Linux executable reporting v2.3.2, using the beta build channel and explicit version. Its tool registry and permission baseline tests passed (47 and 124 respectively). This is a build check, not a signed release or Bud integration test.
- Fetched Hermes v0.23.2 at `ae2a81ccc00e9b7c06301523e5bb09608397149c`. Its supported editable installation built and reported v0.23.2. Upstream middleware, managed-dispatch concurrency and terminal-approval batching tests passed (5, 2 and 7 respectively). Bud's Signal plugin tests passed (58).
- Added pinned stock-runtime probes. They demonstrate that OpenCode can transform arguments after `tool.execute.before`, use saved `always` permission rules, rewrite shell execution later, and expose a plugin permission-reply capability. The plugin probe uses a stand-in permission service and does not prove a complete impersonation exploit. Hermes probes demonstrate argument rewrites after the pre-tool hook, a direct registry path outside the managed dispatcher, its managed dispatch's duplicate-callback protection, and terminal retries after an uncertain acknowledgement. These are negative baseline probes: their passing results do not establish approval security.
- Selected fail-closed authenticated one-shot review as the intended behavior. Saved or permanent grants, unattended calls, unavailable review surfaces and uncertain acknowledgements cannot satisfy it. Review must bind the final resolved effect, including shell execution context, after all relevant rewrites. A failed or uncertain execution spends its approval and must not be retried under that approval. Native guardrails and the existing Signal reaction/code flow must remain in force.
- Identified additional work before enabling the contract: cover alternate and nested dispatch paths and effectful leaves, prove owning-connection or authenticated Signal reviewer routing, establish isolation from agent-controlled tools (same-user file permissions alone are insufficient), and distribute identifiable patched runtime builds rather than silently using stock runtimes. Runtime plugins execute in the trusted process and require an explicit trust boundary.
- `go test -race ./internal/approval`, the four OpenCode probes and the four Hermes probes passed locally. A full `go test ./...` run encountered environment-sensitive temporary-directory project detection, file-mode and process-cleanup failures; it is not recorded as passing. The probe instructions require trusted disposable source trees and dependencies; the OpenCode test harness is not an OS network sandbox.
- A separate isolated host checkout at `5f0bc75137ab203bde821ce984e3b72a57310a54` passed the approval tests with and without `-race` and all 58 Signal plugin tests. Its default Go cache was read-only; a temporary `GOCACHE` resolved that. The pinned upstream probes on that host are still pending.
