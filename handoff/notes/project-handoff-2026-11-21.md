## What was decided (summary; the log is authoritative)
- Fully off Claude architecture. Models: OpenCode Go Plus ($40/mo, Jason subscribed; OpenAI-compatible API) plus a local Qwen 35B MoE on a separate box (RX 6700 XT 12 GB, 32 GB DDR5; llama.cpp; Wake-on-LAN when private work is queued; tuning and FIM model deferred).
- Runtimes: Hermes Agent is the 24/7 home-server manager (changes required: manual approvals wired to the tiers, skill and memory writes staged for review, synced skills locked, terminal in Docker, plus a plugin so Signal reactions answer approvals). OpenCode is the local coding harness; a small OpenCode server on the home server serves IDE planning chats. Both are bootstrapped by the Bud installer.
- Repos: jgarner9/bud (public) grows into the monorepo: cmd/bud + internal/ (one Go module, stdlib only), ide/ (embedded Neovim config), app/ (Tauri 2, shipped via TestFlight/dmg/AppImage, never via sync), server/ (Hermes, planning OpenCode, router, curator, Hugo KB site), content/ (AGENTS.md, skills, agents, commands, plugins, env/ with registry.jsonc), profiles/ (examples only), docs/, scripts/. Private jgarner9/bud-overlay holds device profiles, personal env, op:// secrets and personal skills, merged over the public repo by path and ID (overlay wins). Private bud-kb holds the knowledge base (Markdown pages only). bud-brain stays a private archive. CI on bud must block personal leaks.
- Registry: content/env/registry.jsonc maps nine roles (manager, coding, planning, classifier, FIM, embedding, fallback, curator, vision) to models; `bud sync` renders every runtime's config from it; `bud doctor` catches drift; runtimes sit behind thin adapters.
- Updates: code and content are signed, and devices refuse unsigned or downgraded updates (overlay unsigned, pulled over SSH). Stable and edge channels; code and content versioned separately; laptop on edge, home server on stable.
- Secrets: 1Password via op:// references and a service account scoped to a "Bud" vault; the agent never reads values.
- Action tiers: do alone (reads, search, memory, drafts, texts to Jason, tests/linters/read-only git/metrics/make/docker/npm with exceptions); ask in the editor (git commit and other workspace commands); approve by phone (sends, pushes to main, spending, infrastructure, secrets); never (delete vault items, reveal secrets, disable approvals). Approvals: Tauri push first, then Signal after 5 minutes (react to approve or deny, or "yes <code>"); unanswered approvals expire after 1 hour and are denied; pre-approval counts only from Jason directly.
- Messaging: Signal via signal-cli on the home server with a spare T-Mobile number. Jason dislikes Telegram. Mail: iCloud (IMAP/SMTP, app password in 1Password); every send needs approval; cleanup only moves mail to Deleted Messages, with a digest.
- Routing: privacy P0 private (Qwen only) / P1 internal (Go models) / P2 public, with rule-based pre-tagging before Qwen classifies; cost C0 Qwen / C1 Go included / C2 Go top-up capped at about $10 a month.
- Memory: working memory in SQLite (FTS5 + sqlite-vec, embeddings Qwen3-Embedding-0.6B on the home server); Hermes's memory points at it (latency budget 300 ms p95, fallback documented). A nightly curator on Qwen promotes facts to bud-kb after 2 mentions or on request; pages flagged at 6 months unreferenced, archived (never deleted) at 12; evergreen pages get refresh checks.
- IDE: opencode.nvim (pinned to a reviewed commit, no fork unless needed) plus a bud-owned server switch; :BudGen kept; inline completion Qwen FIM first, fallback MiMo-V2.6-Flash on Go via minuet-ai.nvim, never on P0.
- Linear holds dev TODOs; the KB is reference docs and does not mirror Linear. Hugo builds the KB site on the tailnet. Headroom is an optional token saver (not an embedding model).
- Self-improvement loop: Bud observes, proposes diffs to a review queue, Jason approves, edge-first rollout with revert, plus a weekly landscape scan.
