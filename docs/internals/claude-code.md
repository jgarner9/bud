# Claude Code, clod and the dashboard banner

How bud finds, checks and sets up Claude Code, and how it sets up clod.

**Claude Code.** `internal/claude` finds the `claude` binary (PATH, else the native installer's `~/.local/bin/claude`) and reads `--version` and `auth status --json` (`Check`; a cloud provider's `apiProvider` becomes `Method`, e.g. "Amazon Bedrock"). When logged out in bud's own dir while `~/.claude/settings.json`'s `env` turns on Bedrock/Vertex/Foundry, `Status.Elsewhere` names it (Lua: `claude.home_provider()`), and status, setup, install, doctor and the session say to share the dir (`ai.claude.config home`) instead of running `claude auth login` (JGA-145); setup and install offer to switch to sharing (`shareClaudeDir`, only when `CLAUDE_CONFIG_DIR` is bud's own, D76). The first kit sync into `~/.claude` lists what it adds and asks (`confirmShared` in `internal/cli/kit.go`), and `bud kit unsync` takes the kit out and drops the ledger. `bud claude status|setup` (`internal/cli/claude.go`): `setup` runs Anthropic's native installer (`claude.InstallScript`, after showing it and asking, or with `--yes`), then hands over to `claude auth login`, which needs a terminal. `bud install` offers it when `ai.claude.autostart` is on (`installClaude`) and only warns if it fails. **clod** (D89, D90, `internal/cli/clod.go`): your private Claude Code setup repo, the `clod.repo` setting else `<gh login>/clod` (`clodRepoFor`, `ghLogin`); bud knows only `~/clod` (`paths.Clod`) and that an `install.sh` at its root taking `--yes` sets it up, never what it sets up. A repo that doesn't exist (`ghRepoExists`) is made from `clodTemplate` (`jgarner9/clod-template`, `createClod`: only after a typed yes, never under `--yes`, and it waits on `ghHasInstaller`); `clod.repo` must match `githubRepo`. `setupClod` asks once (Enter is yes), installs `clodRunDeps` (`bash`, `jq`) and, to clone, `ghDep` through `installClodDeps`, runs `gh auth login` when `ghLoggedIn` says no (even under `--yes` at a terminal, `stdinTerminal`), `gh repo clone`s into `~/clod.clone` and moves it in whole (a cut-short clone leaves nothing), and runs the installer with `runOnTerminal`; `bud install` and `bud claude setup` call it through `clodSetup` before the kit sync, `bud update` through `offerClod`, which honours a no (`paths.ClodDeclined`, a marker like `KitDeclined`: `hasMarker`/`setMarker`) and `ai.claude.autostart` off; `ghLoggedIn` checks github.com only; `bud uninstall` lists `~/clod` as kept. Installed (`clodInstalled`) is bud's record (`paths.ClodRecord`, `clod.json`: repo as owner/name via `githubName`, commit, time, git asked only when `~/clod/.git` exists; `writeClodRecord` after `install.sh` succeeds) while `~/clod/install.sh` is still there, or, from Jason's clod, a `~/.local/bin/clod` link that resolves or `clod` on PATH. `TestMain` (`internal/cli/main_test.go`) turns `clodSetup` off for every cli test; `clod_test.go` puts the real one back with the package manager, gh and PATH faked. Claude Code config dir (D73, D77, JGA-169): bud shares `~/.claude` by default (`ai.claude.config` `home`); with `bud`, `cli.UseClaudeConfig` (from `main`, never in tests) sets `CLAUDE_CONFIG_DIR` to `paths.ClaudeConfig()` unless it's already set; `moveKit` (`internal/cli/claudedir.go`) takes the kit out of the dir in the ledger's `Dir` (`kit.Unsync`, under `withClaudeDir`) before `syncKitWith` syncs into the current one. Doctor's `claude code` check (`doctor.ClaudeCheck`) only ever warns, with fix `bud claude setup`; the dashboard pulls it out of the doctor count into its own banner, and `c` runs the fix. bud stores no keys (D26). Tests swap `checkClaude` and `runOnTerminal`.
