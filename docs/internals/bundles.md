# Desktop app bundles

`bud bundle`, the macOS and Linux apps and how they stay current.

**Bundles.** `bud bundle [--macos|--linux] [--dest]` (`internal/cli/bundle.go`) builds the desktop app. `internal/bundle.Mac.Build` builds in a temp dir beside the destination, re-signs with `codesign --force --deep -s -` and renames it in. With Kitty as the terminal (`bundleKitty`, swapped in tests) it's a copy of kitty.app (D97, JGA-185, `Mac.kitty`): a `cp -c` clone of the resolved kitty.app (a linked one is never edited), `plutil` sets the name, `MacID`, `bud.icns` and `LSEnvironment.KITTY_CONFIG_DIRECTORY` (`ConfigDirFor` the absolute dest, keeping kitty's own key) and drops kitty's URL schemes and Services, and `kittyFiles` writes `Contents/Resources/bud-kitty/` (`kitty.conf` including yours, found by `userKitty` in kitty's own search order and skipping Bud's dir, and giving programs in Bud your config dir via `env KITTY_CONFIG_DIRECTORY`; `macos-launch-services-cmdline` running `launchArgv`'s `bud open`; `launch-actions.conf` for drops; the two run with `BUD_APP=start`/`drop` (`withApp`), and `bud.app` (`nvim/lua/bud/app.lua`, `tests/lua/app_test.lua`) has each of the two nvims leave `app-start`/`app-drop` in the state dir (`bud.startup.began` and its server address) and look for the other's; whichever is second pairs them when the buds started within 3 s and the other's server takes a connection (notifications only, so neither waits on the other), and the dashboard `yield`s, quitting only while untouched (floats like ui2's don't count; never headless), so a drop on a closed Bud opens one window, JGA-186); `BudKitty`/`BudKittyVersion` in `Info.plist` (`ReadMac`, one `plutil` call) with `BudBin`, the staleness rules in `bundle.MacInfo.Stale` (a `Want`: another bud built it or it runs another bud, the wrong kind or another kitty.app, kitty updated or gone, moved), which doctor's `Bud app` check (`checkBudApp`, macOS only, swap `findBundles`, `readMac`, `bundle.KittyVersion`, `doctorGOOS`) and the update refresh share. Otherwise (D47) it runs `osacompile` on the embedded `bundles/macos/main.applescript` (`bud.Bundles()`), with this bud's path and `PATH` filled in, and edits `Info.plist`; both write the icon from `Icon()` (pixel art from the `robot` grid, encoded as `.icns`). It only replaces an app whose bundle id is `MacID`. `TestBuildKittyCopy` builds one from a fake kitty.app. `TestBuild` needs `osacompile`, which the sandbox blocks, so it skips there. On Linux, `bundle.Linux.Install` writes `bud.desktop` from `bundles/linux/bud.desktop` (`paths.DesktopEntry`, `paths.DesktopIcon`), quoting `Exec` by the desktop entry spec (`execArg`, then `desktopValue`), and only replaces an entry carrying `X-Bud-Version`. The app runs install.sh's recorded binary when there is one (`bundleBin`), whose path a self-update keeps, so updates never need to rebuild it. `bud install` on the full profile runs `bud bundle` after the sync (`installBundle`) and only warns if it fails; `bud uninstall` removes what `bundle.Find` reports (tests stub `findBundles`, so they never see a real `/Applications/Bud.app`).
