# The AI session and its features

`bud.ai.agent` (OpenCode over ACP) and everything built on it: the pane, chat, permissions, inline actions, tools, the generator, filing issues and working them. The transport itself is in [acp.md](acp.md). OpenCode is the only agent the IDE runs (Suite D139, BASE D154); the one exception is `bud.ai.work`'s cloud path (`ai.work.where = "cloud"`, which runs `claude --cloud`), which JGA-406 deletes.

**The session.** `bud.ai.session` is `bud.ai.agent` and nothing else; every consumer requires it and calls `session`, `send`, `on`, `interrupt`, `status`, `stop`, `restart`, `drop`, `get` and `list` on it. `agent.setup()` runs from VimEnter on `vim.schedule` (not headless, so after the first screen, D35): the keys `<leader>ch` (chat toggle), `<leader>ac` (the pane, or opencode.nvim, see `bud.ai.term.chat_key`), `<leader>aF` (full screen), `<leader>ar` (restart the session) and `<leader>as` (share the selection), `:BudChat`, `:BudAgent status|restart|stop|option`, the status line section, the idle reap, the setups of `bud.ai.actions`, `bud.ai.issue` and `bud.ai.view`, and a session for `bud <dir>` (`BUD_OPEN=project`) or for files. `bud.open.go` calls `agent.opened(path)` for a project opened from inside bud, which starts its session unless `ai.agent.autostart` is off. At most `agent.max_sessions` (3) run, least recently used goes first, and `reap` stops ones idle past `ai.agent.idle_minutes`; a stopped one restarts on the next `send`. `ide/tests/lua/agent_test.lua` drives it with the fake ACP agent.

**The pane** (`bud.ai.term`, D48). OpenCode's own TUI (`agent.tui(root)`, `opencode <root>`) in a terminal, one per project. `toggle` shows and hides it (hiding keeps it running until it has been hidden and unused for `ai.agent.idle_minutes`, then `reap` ends it), `send(text)` types a prompt in (opening it without taking the cursor, and waiting for it to draw), and it is the layout's `chat` pane (`layout/panes.lua`). Its window is a side pane (`vim.w.bud_side`): `bud.terminal.arrange` (D82) keeps side panes beside the editor and the `<leader>t` terminal under them, right of the full-height explorer. `bud.escape` (D84) makes `jk` leave Insert mode and, in the terminal, this pane and chat (`escape.attach`), go to Normal mode: only `k` is mapped, `vim.on_key` records the last non-`k` key, a `k` within `escape.window` ms of a `j` backspaces it and leaves; Esc isn't mapped (`ide/tests/lua/escape_test.lua`); `<leader>w` is `<C-w>` (`core/keymaps.lua`). `bud.quit` (D83) ends the AI panes, chat and home planning pane (`stop_all`) and an idle shell (`terminal.job()`, no children via `nvim_get_proc_children`) on `ExitPre`, so `:wqa` isn't refused (E948), but nothing while unsaved files make a `:qa` fail (`settles` reads the command from history); `<leader>qq`/`qw`/`qQ` quit, save all and quit, quit without saving. Tests: `term_test.lua`, `quit_test.lua`.

**Permissions** (D52, D134). `agent.permission` hands each ACP `session/request_permission` to `bud.ai.permissions.acp`: an edit opens as a diff in `bud.ai.review` (accept with `ga`, `:w`, `ZZ` or `:x`; reject with `q` or by closing it; a diff you change is accepted as the agent's, since ACP's answer can't carry an edited version), anything else a float (`y`/`a`/`n`/`r`), queued one at a time, with `a` remembered per project and command. An edit outside the session's project is refused before anything opens it. `permissions.policies` answer some requests without asking (`bud.ai.issue`'s Linear writes, `bud.ai.work`'s edits inside its worktree), and `permissions.withdraw` takes back a question when its turn is interrupted. `ide/tests/lua/permissions_test.lua` covers it; the diff UI is covered through it and by `bigfile_test.lua`.

**Chat** (D81, JGA-165, D150). `<leader>ac` opens opencode.nvim (`bud.ai.opencode`, see neovim.md). `bud.ai.chat` is the other chat: OpenCode's TUI in its own tab (dashboard `c`, `<leader>ch`, `:BudChat`) in `~/.local/state/bud/chat/` (`M.dir`), so no project's instructions load, and its exit closes the tab; OpenCode's `/sessions` picks an earlier conversation. It uses no `bud.ai.agent` session. With `ai.agent.chat_ui = "bud"` chat is bud's own buffer instead (`bud.ai.view`, see acp.md). `ide/tests/lua/chat_test.lua`, `chat_key_test.lua`, `opencode_test.lua`.

**Inline actions** (`bud.ai.actions`, JGA-90): `<leader>ae`/`af`/`at` type explain/refactor/write-tests for the selection (`main.go lines 3-4`, `actions.mention`) into the project's TUI (`term.send`), whose edits arrive as permission diffs; `<leader>am` in a gitcommit buffer (or `:BudCommitMessage`) sends the staged diff and recent subjects to the session and puts the `done` reply above git's comments. `ide/tests/lua/actions_test.lua`.

**Tools** (D54): `bud.tools` loads `ide/tools/` (embedded, mounted like `ide/languages/`, `paths.Tools`) and `user-tools/<name>/` after the first screen; `bud tools ls|enable|disable [--reason]|rm|promote` (`internal/cli/tools.go`) owns `tools.disabled` in `config.json` and `tools.json` in the state dir. Tests: `ide/tests/lua/tools_test.lua`, `internal/cli/tools_test.go` (swap `runGit`).

**Generator** (D55): `bud.gen.run(request)` (`:BudGen`, or `bud tools gen` via `BUD_OPEN=gen`/`BUD_GEN`) runs session key `gen` in `user-tools/` with `gen.prompt`, snapshots the dir, shows the conversation in a log buffer (`gen.buf()`, `i` asks for changes), and after each `done` load-tests what `gen.changed` finds (`gen.load_test`, a headless nvim) and enables or disables it through the CLI. `ide/tests/lua/gen_test.lua`: the fake ACP agent "writes" the files (`FAKE_ACP_RUN`, see acp.md).

**Filing issues** (D70, JGA-125): `bud.ai.issue` (`<leader>ai`, `<leader>aB`, `:BudIssue [bud]`, `:BudIssues`) takes a report in a float with `context()` attached, runs the `file-issue` skill (synced content) in a keyed session (`start`), parses the reply's fenced `bud-issues`/`bud-filed` blocks (`parse`), and shows the review (`review_lines`); `policy` (in `bud.ai.permissions.policies`) denies Linear writes until the reviewed proposal is sent. `ide/tests/lua/issue_test.lua` (swap `M.bud`; the fake agent answers from `FAKE_ACP_REPLIES`). `bud.ai.work` (D71, `w` in `:BudIssues`, `<leader>aw`, `:BudIssue work ID`) has the agent fix one in `<repo>.worktrees/<id>` (`prepare`), with `policy` accepting edits `inside` it; `ide/tests/lua/work_test.lua`. Sessions are keyed (`agent.session(root, { key = ... })`, `get`, `drop`), and `extra = true` keeps one (issue, work, gen) from counting against the project sessions. **Issue targets** (JGA-123): `bud issue target [--bud] [--json] [dir]|set --team T [--project P] [--global] [project]|unset` (`internal/cli/issue.go`) say where an issue filed from the editor goes: a project's `issues` in `projects.json`, else `ai.issues.team`/`project`, and `ai.issues.bud` (bud's own tracker) for issues about bud, whose root is the dev-linked checkout.
